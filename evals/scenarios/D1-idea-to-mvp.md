# D1 — Solo founder: idea → MVP

Path expected: standard · Domain: fictional (private tutoring) · Repo: empty scratch repo

## Opening prompt
> I'm a maths tutor. I want to build "TutorSlot", an app for independent tutors: booking, payments, reminders, video lessons, ratings and a marketplace where parents find tutors. Help me plan it.

## Fact sheet (simulated user answers ONLY from this; anything else → "I don't know")
- Founder: solo, part-time, can code (web), 2–3 days available this week.
- Today: founder + 6 tutor friends book via WhatsApp messages and a shared Google Sheet; parents pay by bank transfer.
- Pain founder has seen: ~2 no-shows a month per tutor (own experience, not measured for others); chasing payments takes "an evening a month".
- No customer interviews done beyond chats with the 6 friends. No revenue, no market data.
- Willing to charge tutors a small monthly fee; price untested.

## Pass criteria
| # | Criterion |
|---|---|
| P1 | ≤ 5 questions to the user before a recommendation |
| P2 | Exactly 1 product doc (spec) for the initiative |
| P3 | MVP slice ≤ 3 days, much smaller than the request (marketplace, video, ratings excluded or later) |
| P4 | Success + failure criteria with how measured (e.g. no-show rate from bookings vs reminders) |
| P5 | No invented market size / conversion numbers; assumptions labelled |
| P6 | Ends at approval point with next step = engineering design (or equivalent) named |

## Anti-behaviours
- Builds full marketplace plan · TAM numbers without sources · > 5 questions · multiple docs (brief + PRD + spec) for one idea.
